Решение проблем
В бэкапах пусто, хотя файлы на диске есть
  • Запустите индексер вручную: python3 /opt/collector/backup_indexer.py --prune --diff и смотрите вывод
  • Проверьте, что имя папки совпадает с new_name локации (регистр важен!)
  • «Orphan-папки» в выводе индексера — папки, которым нет локации в БД
Локация без бэкапов
  • Устройство недоступно в момент прогона — проверьте ping и SSH
  • Проверьте креды устройства в справочнике «Учётные данные»: логин/пароль, порты SSH (для бэкапа) и API
  • Прогоните бэкап вручную — увидите точную причину: python3 /opt/collector/backup.py --ip <адрес>
  • Итоговый отчёт ночного прогона — в логе /var/log/macatlas/backup_py.log
Новое устройство/локация не бэкапится

Ничего перегенерировать не нужно: backup.py читает устройства прямо из БД при каждом запуске. Проверьте, что у устройства заполнены активность, IP и креды (у объекта — LAN и креды) — и запустите задачу backup_py вручную из «Настроек системы».

Задача cron не запускается
  • «Настройки системы» → «Задачи планировщика»: задача включена, расписание корректное
  • crontab -l — есть строка job_runner.py и блок MacAtlas jobs
  • Лог диспетчера: /var/log/macatlas/job_runner.log
  • После ручных правок collector_jobs в БД: INSERT INTO app_settings (name,value) VALUES ('crontab_dirty','1') ON DUPLICATE KEY UPDATE value='1';
«Duplicate entry» в индексере

В базе две локации с одинаковым new_name. Найдите дубль:

SELECT new_name, COUNT(*) c FROM locations GROUP BY new_name HAVING c > 1;

В модуле «Локации» колонка «Привязка» показывает, к какой из них привязаны объекты — пустую можно удалять.

Доменная авторизация не работает
  • Проверьте настройки LDAP в интерфейсе: «Настройки системы» → «Доменная авторизация (LDAP)» (домен, контроллер, порт) — в config.json этих параметров нет
  • Проверьте доступность контроллера с сервера: nc -zv <host> 389
  • Локальный вход работает независимо — используйте его для диагностики
Изменили functions.php — красная плашка о целостности

Хэш контрольного файла пересчитывается скриптом integrity_hash.py (хранится у владельца, не на сервере). После любых правок core/functions.php запустите его — он обновит хэш в core/acl.php.
